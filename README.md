# 复拍对齐相机

同一个位置、不同时间拍的照片，自动**归类 → 对齐 → 对比变化**。

- 画面里有**二维码**：按码归到对应测点，再用码的四个角 + 三个圆点 + 照片自身纹理一起对齐，精度最高，还能发现靶标被移动。
- **没有二维码**：靠照片自身的图像特征，自动判断属于哪个测点。只有一个测点明显吻合时才自动归入。几个位置长得很像（背景相同）时，会提示"有歧义"，请你贴码或手选，不会乱归。
- 拍照时实时引导：显示参考照片的取景框和半透明叠加，提示"靠近 / 后退 / 左移 / 转一点"，对准后快门变绿。
- **批量作业**：第一次「批量建档」每张一个测点（记下位置、镜头朝向），下次「批量复拍」按 二维码 / 位置 + 朝向 + 图像 自动匹配；认不出的进「待确认」，不乱归。
- **电脑端后处理**：手机「导出全部」→ 浏览器打开 `web/index.html` 查看、筛选、打印报告；`python/report.py` 在电脑上重新分析并出 HTML 报告。

## 目录

| 路径 | 内容 |
|---|---|
| `复拍对齐相机.apk` | 安卓安装包（Android 8.0 以上、64 位手机） |
| `targets/` | 可打印靶标（A4，100% 比例打印） |
| `android/` | 安卓 App 源码（Kotlin + Jetpack Compose + CameraX + ML Kit + OpenCV） |
| `python/` | 电脑端同一套算法：用真实照片调参、批量归档；`defects.py` 是病害检测基元（与 App 的 `Defects.kt` 同一套） |
| `web/index.html` | 电脑端后处理网页：打开手机导出的 ZIP，前后对比、病害标注、筛选、打印报告（纯本地，不上传，不依赖外部库） |
| `samples/` | 合成测试照片和真值（`python/synth_test.py`、`make_defect_samples.py`、`make_hard_samples.py` 生成） |

## 手机上怎么用

1. **安装**：把 `复拍对齐相机.apk` 传到手机，打开安装（需要允许"安装未知来源应用"）。
2. **准备靶标（可选）**：首页「**生成靶标**」批量生成编号二维码（如 T0001–T0024，A4 每页 6 个，按 100% 打印；电脑上也可用网站「靶标」页或 `python make_target.py --sheet T 1 24`）。每个标签 = 40 mm 二维码 + 3 个圆点，剪开后二维码贴在裂缝旁、圆点分散贴在周围。
   - 圆点要分散、不在一条直线上，不要遮挡要观察的病害；同一个编号只贴一处。
   - 下次生成默认从上次最后一号往后接；生成已建档的编号会提醒。
   - **编号对应**：首页「编号对应」把靶标编号对上项目编号 / 名称（逐个填，或导出 CSV 在电脑上填好再导入，列为 编号、项目编号、名称、备注）。已建档的测点自动改名；还没拍的编号，第一次拍到时直接用对应名称建档。
3. **首页**：右上角「教程」「设置」；一个主按钮「**拍照**」，下面两个次要入口「复拍指定测点」「只建新测点」；再往下是概况（测点 / 需关注 / 待确认）、工具格（生成靶标、编号对应、导入照片、导出全部、电脑端处理、测点地图），规划中的功能（巡检任务、云端同步、RTK）收在一行「即将推出」里；最下面是「需要关注」和全部测点。第一次打开会先显示图文教程。
   - **拍照**（一张或多张都行）：认识的编号 → 归入原测点；新编号 → 建测点；无码 → 先按定位和镜头朝向挑出附近测点，再用图像确认**唯一吻合**才归入；附近一个测点都没有（新位置）→ 自动建档；附近有测点但认不准、或没有定位 → 进「**待确认**」，不乱归、不重复建档。拍完不跳页，接着拍下一处。底部可改新测点的病害类型。
   - **只建新测点**：每张都建一个新测点（名称“测点 月日-序号”，有二维码按码或对应表命名）。
   - **复拍指定测点**：先选测点，相机上叠加上次的照片，对准了再拍，拍完直接看对比。
   - 二维码相同但画面和参考对不上（同一个码贴到了别处），相机底部会提示“⚠ 画面和参考不一致，请复核”。
   - **待确认**：点一张，按图像相似度和距离列出候选，选「归入」或「新建测点」；也可以「全部新建」。
   - 只想给某一个测点复拍：进测点页点「复拍」，拍完直接看对比（下面第 4 步）。
   以下是单个测点的细节：
   **第一次拍**：
   - **大场景（推荐）**：先靠近二维码扫一下，顶部出现「已扫码：新编号」后**后退**，把整个场景拍进画面再按快门。二维码在照片里很小、甚至不入镜都可以，编号用刚才扫到的。
   - 小范围：直接连二维码一起拍，确认绿圈圆点（点按可增减），然后保存。
   - 无二维码：起个名字建测点。允许定位的话会记下拍摄位置，以后按**位置 + 画面特征**自动识别。
   - 这张就是**参考照片**，以后的照片都和它比。
4. **以后复拍**：在测点页点「复拍」，或首页「扫码 / 拍照」后扫码。扫码后测点就**锁定**了（顶部有锁形提示，可点「解锁」），离开二维码、后退到参考位置也不会丢；按半透明参考和提示对准，快门变绿后拍。
   - 没有二维码时：附近（按手机定位）的测点里按画面特征自动识别；背景相似、只看画面分不清的两个地方，只要相距超出定位误差，就能靠位置区分。离所有测点都很远时不会乱猜，会让你手选。拍完自动对齐、对比，默认显示「**标注**」（原有裂缝黄色、新增红色，框出剥落等面状病害），另有五种看法：
   - **滑动**：左参考、右新图，拖动分界线
   - **叠加**：调新图透明度
   - **闪烁**：两图交替显示，变化处会"跳"
   - **变化**：红色加黄框是**结构变化**（裂缝、剥落、新物体），计入变化率；浅蓝加蓝框是**明暗变化**（阴影、水渍、光照不均），单独列出、不计入变化率；灰白是**反光/过曝**，未参与比较
   - **原图**：未对齐的原始照片
   - 有反光、模糊、偏暗时，对比页顶部会给出**拍摄质量提示**，可一键「删除并重拍」
   - 测点页顶部有**结构变化走势**图（两张以上复拍后出现），看病害是否在发展
   - **镜头朝向**：拍照时记录镜头朝向（北偏多少度）和俯仰角。同一点位不同方向的照片属于不同测点：识别时只在**位置附近且朝向吻合**（±60°、俯仰 ±30°）的测点里找；复拍时相机页提示"比参考偏右 20°，向左转"。附近有钢轨、钢结构时指南针可能不准，会提示"手机画 8 字校准"，此时只记录俯仰角。
   - **病害结论**：按测点类型给出（见下文“测点病害类型”）。只测裂缝时，对比页顶部的「病害结论」给出裂缝条数、总长、最大宽度、比上次新增的长度和判定（稳定 / 延长 / 变宽 / 新增），「标注」视图里原有裂缝黄色、新增部分红色。参考照片里有二维码时自动换算成毫米（二维码默认 40 mm，可在测点页菜单「二维码尺寸」修改，或把尺寸写进码里如 `K12+345;40mm`）；没有码时用像素表示。
   - 测点页的走势图可切换"结构变化 / 裂缝总长"，并给出测点结论，如"共 5 次复拍（120 天）：裂缝总长 132.7 → 192.1 mm，平均每 30 天 +14.8 mm；判定：持续发展"。
5. **任选两次对比**：对比页上方「对比基准」默认是参考照片，可以改选同测点的任意一张，比如上一次，用来看"这个月比上个月"的变化。
6. **分享**：对比页右上角的分享按钮，把变化图、对齐图、基准图和说明文字发到微信、邮件等。
7. **导入**：首页右上角「导入」可以选相册照片；也可以在相册或其他相机里"分享"给本应用。多张照片会逐张自动归类，遇到需要确认的会停下来问你。

### 对齐状态的含义

| 状态 | 含义 | 建议 |
|---|---|---|
| 已对齐 | 靶标和表面纹理两套独立依据结果一致 | 可直接用 |
| 特征对齐 | 无靶标，按照片纹理对齐 | 一般可用 |
| 待确认 | 靶标正常，但表面太光滑，无法用纹理复核 | 人工看一眼叠加图 |
| 圆点异常 | 某个圆点不见了或位置变了（已自动剔除） | 检查圆点是否脱落、被遮挡 |
| 需复核 | 靶标和表面纹理对不上，靶标可能被整体移动过 | 一定要人工核对 |

"整体相似度"低于 0.5 时会单独提示：可能拍的不是同一处，或表面整体变了（翻新、积水、遮挡）。

## 测点病害类型（小场景）

每个测点建档时选它拍什么（可多选），以后复拍自动按类型分析；在测点页菜单「病害类型」可以改，改完已有照片会重新分析。什么都不选 = 通用（裂缝 + 面状 + 位移）。

| 分组 | 类型 | 手机上给出 | 适用 |
|---|---|---|---|
| 线状 | 裂缝 | 条数、总长、最大宽度、比上次新增多少 | 混凝土裂缝、焊缝裂纹、轨枕裂纹 |
| 面状 | 剥落/掉块、渗水/水渍、泛碱/白化、锈蚀/涂层 | 每处的类别和面积（cm²） | 二衬掉块、渗漏水、泛碱、钢构件锈蚀与涂层剥落 |
| 位移 | 伸缩缝/接缝、错台/位移 | 一侧相对另一侧移动多少毫米，分解为“张开/闭合”和“错动” | 伸缩缝、管片接缝、支座、轨缝、扣件移位 |
| 部件 | 螺栓、扣件/部件 | 防松标记线：正常 / 疑似松动（转角）/ 残缺；部件疑似缺失或新增 | 钢结构螺栓群、轨道扣件、声屏障螺栓 |

结论统一分四级：**无变化 / 轻微 / 明显 / 建议重点关注**（只选“裂缝”的测点仍用 稳定 / 延长 / 变宽 / 新增）。对比页「标注」视图里：A = 面状变化（红 剥落、橙 锈蚀、蓝 渗水、紫 泛碱），D = 整体位移（箭头为方向），M = 防松标记（绿 正常、红 疑似松动、橙 残缺），P = 部件变化，编号和结论卡里的明细一一对应。

**类型写进二维码，现场不用选**：在编号后面用分号加类型，扫码建档时自动选好，例如 `B01-Z023;40mm;螺栓`、`Q12-03;伸缩缝,裂缝`、`T7;渗水;掉块`（也认英文 `crack / joint / offset / spall / seep / effl / rust / bolt / part`）。

**各类怎么拍**

- **螺栓**：用红色或黄色油漆，在螺母、垫片和钢板上画一条连续直线（防松标记）。螺母转动后这条线会断开、错开，App 量出转角。白色标记线目前识别不了。
- **伸缩缝、接缝、支座**：二维码贴在缝的一侧，画面里两侧都要拍进去，各占一部分。量的是“照片平面内”的移动（张开、错动）；管片错台这种垂直于墙面的高差，正对着拍看不出来，要斜着沿缝拍，或在缝边放一把小角尺。
- **剥落、渗水、泛碱、锈蚀**：正对表面拍，二维码贴在 30–50 cm 内。渗水、泛碱按颜色明暗判断，可能和阴影、潮湿、污渍混淆，结论里会提示人工确认。
- 手机上只给初步判断；要做精细识别，在测点菜单「导出全部」，ZIP 里每张照片有 `findings.json`（区域轮廓、位移向量、标记线角度等，坐标都在参考照片坐标系下）和标注图，`zone.json` 是测点信息。

**合成样例测试**（`python/make_defect_samples.py` 生成，`python/test_defects.py` 和设备端 `DefectsDeviceTest` 用同一批样例、同一判定标准；“今天”那张都换了角度、偏暖偏暗、有光照梯度）：12 个用例全部通过。

| 用例 | 真值 | 手机实测 |
|---|---|---|
| 剥落 / 锈蚀 / 渗水 / 泛碱 | 20.4 / 12.4 / 43.5 / 19.1 cm² | 类别全对；面积 22.8 / 13.9 / 49.2 / 21.1 cm²（偏大 10–15%，边缘过渡区计入） |
| 错台（错动） | 3.0 mm | 错动 3.0 mm |
| 接缝张开 | 2.0 mm / 1.0 mm | 张开 2.1 mm / 1.0 mm |
| 螺栓：1 个转 25°、1 个缺失 | — | 疑似松动（转角约 26°）+ 标记残缺 + 部件疑似缺失 |
| 螺栓：1 个转 10° | — | 疑似松动（转角约 11°） |
| 三组无变化对照 | — | 均无误报 |

**检测下限**（1 米左右拍摄、二维码 40 mm、约 0.23 mm/像素，`python/probe_limits.py`）：剥落/掉块约 1 cm²；位移约 1 mm（4 像素），0.5 mm 测不出；螺母转角约 10°，5° 测不出。强光照差（一侧暗一半、明显偏色）无误报。

### 弯曲裂缝和剥落：难样例（`python/make_hard_samples.py` → `python/test_hard.py`，设备端 `DefectsDeviceTest.hardCases`）

现场常见、而简单样例覆盖不到的情况：蜿蜒/分叉/粗细渐变的裂缝、龟裂网，浅色新断面、露筋、阴影干扰。改进前只通过 3/11，现在 10/11（剩下一例在检测下限，只记录）：

| 用例 | 改进前的问题 | 现在 |
|---|---|---|
| 蜿蜒裂缝延长 + 新分叉 | 被拆成 3 段 | 1 条主缝 + 1 条新分叉，新增 216 mm（真值 197） |
| 蜿蜒裂缝无变化 / 龟裂网无变化 | 拆成多段；网状被误判“新增” | 稳定 |
| 细裂缝变宽（0.3 → 0.7 mm） | 细缝拆成 11 段，误判“延长” | 变宽 |
| 浅色新断面剥落 | 判成“泛碱/白化” | 剥落/掉块，面积误差 5% |
| 剥落 + 旁边一大片柔和阴影 | 阴影判成 1 m² 的“渗水”，剥落边缘判成“新增裂缝” | 只报剥落；阴影归为“阴影/光照变化”不计入 |
| 有裂缝的墙面上新剥落 | 裂缝误判“延长且变宽” | 裂缝稳定 + 剥落 |
| 0.3 mm 浅色细裂缝延长 | 检不出 | 仍检不出（约 1.3 像素宽，和粗糙表面纹理一样强）：**细裂缝请靠近拍** |

改了什么（Python 和 App 同步）：
- **断段连接**：裂缝骨架端点沿走向 14 像素内能接上另一段（夹角 ≤30°、中间有微弱裂缝迹象）就连起来；又长又细的弱响应整条保留。
- **变宽判定**：除了最大宽度，也看按长度加权的平均宽度（细缝被拆段时某一段的局部宽度不可靠）。
- **剥落 vs 泛碱**：纹理被替换且更粗糙（露骨料）→ 剥落，不按明暗分；变白但更光滑 → 泛碱。
- **阴影过滤**：只是明暗变化、边缘过渡宽于约 1.5 cm 的大片区域 → “阴影/光照变化”，结论里提一句、不算病害（湿痕、泛碱的边缘要硬得多）。
- **剥落边缘不算裂缝**：剥落、掉块、锈蚀区域外扩 12 像素内的裂缝不计入新增/变宽。
- 很细（接近分辨率极限）的“新裂缝”要 2 倍长度才计入，避免分叉末梢若隐若现造成误报。

真实裂缝数据（DeepCrack）没有退步：检测 F1 87.3% → 87.9%，真实纹理前后对 30/30 延长检出、30/30 无变化无误报。

## 电脑端后处理（网页 + 报告）

手机上只给大致判断；精细分析、正式报告放到电脑上：

1. 手机首页「**导出全部**」（或测点页菜单「导出」），把 ZIP 发到电脑。ZIP 里每个测点一个文件夹：`zone.json`、`report.csv`（Excel 可开）、每张照片的原图/对齐图/变化图/标注图和 `findings.json`（区域轮廓、位移向量、标记线角度等）。
2. 用浏览器（新版 Chrome / Edge / Safari / Firefox）打开 `web/index.html`，把 ZIP 拖进去（可多个）：总览统计、按严重程度排序的测点列表、需关注/待复拍筛选、前后对比滑块、病害标注图、结论和明细；「打印 / 存为 PDF」出报告。数据只在本机浏览器里处理，不上传。以后部署到服务器时可以用 `index.html?zip=地址` 直接打开。
3. 重新分析（调阈值、批量）：

```bash
../.venv/bin/python report.py 导出包.zip --grow-mm 10
```

生成 `导出包_报告/index.html`：每个测点的参考图、电脑复核标注图、电脑复核结论和手机结论对照。裂缝、面状病害在电脑上重算；位移、螺栓、部件暂沿用手机结果。

### 配套网站（deploy/）

`deploy/` 是一个只用 Python 标准库 + 工具包本身的网站：首页、测试图片（每组样例换成独立二维码编号 DEMO-H01 等，方便手机翻拍测试）、在线处理（两张照片对比；导出 ZIP 生成报告）、批量生成靶标、导出包查看器、下载（APK、电脑端工具包、靶标）。

## 定位：手机 GPS / 北斗 / RTK / IMU

- 手机自带 GPS/北斗一般 3~10 米（城市、桥下更差，隧道里没有）。App 只用它**缩小候选范围**，最终以图像确认为准。
- 厘米级要 **RTK**：外接北斗/GNSS RTK 接收机（蓝牙 NMEA）+ 网络差分服务（CORS，NTRIP 协议），固定解 1~2 cm。App 的「设置 → 高精度定位」是占位，接入外接接收机是后续计划。
- **IMU**（陀螺仪、加速度计）适合测镜头朝向和俯仰（App 已在用，用于区分同一位置的不同方向），不适合单独定位：几秒就漂到米级，只能在 RTK 短暂失锁时补几秒。
- 推荐优先级：**二维码 > 位置 + 朝向缩小范围 + 图像确认 > 人工确认**。复拍时按半透明参考对准，本身就把相机位置对到厘米级；测点很密、外观相似又不能贴码时再上 RTK。

## 算法要点

两端实现的是同一套算法：`python/fieldalign.py`，以及它的 Kotlin 移植 `android/.../align/AlignEngine.kt`。修改时两边要同步。

0. **镜头畸变**：先用宽松阈值做特征匹配，估计两张照片各自的径向畸变系数 k（x_d = x_u·(1+k·r²)）。估计分两遍，第二遍剔除残余误匹配。后续几何计算都在去畸变坐标下进行，变换图像时再把畸变加回去。残差改善不明显时 k 取 0，不做校正。
1. **找靶标**：
   - 二维码：OpenCV 读码，取四角并做亚像素细化；读不出时，安卓端用 ML Kit 再试；还不行就先按特征对齐，把码所在区域摆正放大后再解码。
   - 圆点：自适应阈值找深色圆形，按圆度、实心度、对比度、与码的大小比例筛选；同心候选只留最小的。
2. **初始对齐**：用码四角算单应矩阵，把参考照片的圆点"预测"到新照片上，就近配对。圆点不需要编号；四种角点顺序都试一遍，所以倒着拍也行。
3. **补找圆点**：全局没找到的圆点，把预测位置附近摆正到参考视角再找（强透视下圆点很扁）。每找到一个，就用三个定位块角加已找到的圆点重算预测矩阵，再找下一个。
   **圆点是否移动**：
   - 表面纹理可靠时，直接用特征矩阵判断。
   - 纹理不可靠时，用留一法：去掉某个点用其余点拟合，看它偏离多少。阈值取"0.3 倍新照片中的圆点视直径"和"3 倍外推不确定度"中较大的。
   - 至少剩 3 个圆点才继续剔除，再少就无从判断谁动了。
4. **图像特征复核**：遮掉靶标后，SIFT 特征匹配加 RANSAC，独立算出另一个矩阵（无码识别和取景引导为了速度用 ORB）。两者在靶标点上的偏差小于阈值才算"已对齐"；纹理丰富却对不上，判为"需复核"。
5. **融合精算**：靶标点和特征内点一起重新拟合，每个点同等权重。码的第 3 个角（右下角，没有定位块）是推算的，不参与精算。直接匹配的特征不够时（多半是视角太斜），先用靶标矩阵把新照片摆正，再匹配一次。
6. **对比**：
   - 只在"匹配点覆盖的同一平面区域"内比较，自动排除墙外背景的视差。
   - 新照片分辨率更低时（拍得远），在较低的分辨率下比较。
   - 光照归一化（除以局部均值），差分时允许 ±1 像素错位。
   - 用中位数 + MAD 的自适应阈值，再去掉小连通域。
   - **结构 / 明暗分类**：先求两图的对数亮度比，再做大窗口中值滤波。阴影、水渍是乘性变暗，对数比呈台阶状，中值能保留下来；裂缝是细线，会被中值去掉。所以中值之后的残差大，就是结构变化，残差小就是明暗变化。
7. **无码识别**：新照片和每个测点的参考照片做特征匹配。最佳候选至少 40 个内点、覆盖 12% 以上，且不少于第二名的 2 倍，才判为"唯一"。

**这一版做过的精度改进**（每项都有测试对照）：

| 改进 | 效果 |
|---|---|
| 对齐特征由 ORB 换成 SIFT | 倒拿误差 1.15 → 0.13 px |
| 融合时靶标点和特征点等权重（原先靶标占 1/5） | 普通用例误差再降到 0.02 px |
| 畸变优化改为模式搜索，正则项减小 | k 估计误差 0.013 → 0.001 |
| 圆点检测找全部轮廓（原先只找外轮廓） | 纹理强时圆点不再漏检 |
| 圆点摆正到参考视角再找，找到后迭代修正预测 | 极斜视角下扁椭圆圆点能找到 |

| 新照片读不出码时，按特征摆正放大后再解码（安卓端另有 ML Kit 后备） | 码小、码糊也能走完整流程 |
| 在两张照片中较低的分辨率下做对比 | 远拍时假变化减少 |

没有畸变校正时，k=−0.12 的照片会出现 2.6% 的假变化，还会被误判为"圆点异常"。

|---|---|---|
| 软阴影 | 0 | 3.5%（正确归为明暗） |
| 硬阴影 | 0 | 6.5%（正确归为明暗） |
| 硬阴影 + 裂缝延长 | 1 处（裂缝） | 6.5% |
| 裂缝延长 | 1 处 | 0 |

没有这一分类时，一道硬阴影会产生 4.7% 的"变化"，把裂缝完全淹没。

### 拍摄退化压力测试（`test_robustness.py`）

模拟手机实拍常见问题，12 个用例全部对齐（误差均 ≤ 0.16 px），结构变化判断全部正确：

| 用例 | 结果 |
|---|---|
| 强噪声 + JPEG 质量 60（含/不含裂缝） | 无假变化；裂缝检出 |
| 欠曝（亮度 ×0.35）、偏色 | 无假变化 |
| 过曝（亮度 ×1.7，大片死白） | 无假变化；死白区排除并提示"过曝" |
| 运动模糊 11px（含/不含裂缝） | 无假变化；裂缝检出；提示"新照片比参考模糊" |
| 镜面反光（含/不含裂缝） | 无假变化；反光区排除并提示；裂缝检出 |
| 竖拍（照片旋转 90°） | 正常 |
| 低分辨率 1600px（含/不含裂缝） | 无假变化；裂缝检出 |

修复前过曝会产生 354 处假变化（2.2%），反光 14 处（0.9%），运动模糊 2 处。对应改进：
- **反光/过曝/死黑排除**：任一张饱和的像素，加上与饱和核连通、朝"变亮"方向偏离的光晕，不参与比较，在变化图中显示为灰白，并给出占比。
- **清晰度匹配**：比较前自动把较清晰的一张模糊到与另一张一致（搜索最佳 σ），手抖、对焦偏差不再产生假变化。
- **拍摄质量提示**：反光超过 2.5%、新照片明显更糊、照片偏暗时，对比页顶部出现提示，可一键"删除并重拍"。

安卓端在模拟器上跑同样的照片（含畸变、光影、退化用例），状态和变化判断全部一致。
处理速度：单张约 1.7 秒；同一测点连续复拍时缓存参考照片的特征和解码图，约 1.0 秒（优化前 2.5 秒）。

数据：公开数据集 DeepCrack（真实裂缝照片 + 人工标注掩膜；**仅限非商业研究使用**，下载到 `real_data/deepcrack/`，不随 App 分发）。

**1. 检测对不对**（237 张测试集，与人工标注逐像素比，容差 5 像素）

| | 精确率（检出的有多少是真裂缝） | 召回率（真裂缝检出了多少） |
|---|---|---|
| 全部 | 91% | 84% |
| 标注宽 3–6 px | 85% | 83% |
| 标注宽 6–12 px | 93% | 86% |
| 标注宽 >12 px | 94% | 80% |

逐张中位数：精确率 98%、召回率 94%、检出长度/标注长度 1.03。完全漏检 2 张。

**2. 前后对比准不准**（真实纹理造"前后两次"：把真实裂缝后 40% 修补掉当"上次"，原图加随机透视、亮度/对比度、模糊、噪声当"这次"，纯图像特征对齐后比较）

| | 结果 |
|---|---|
| 裂缝延长（175 对） | 99% 判为"延长/新增"；新增长度 测/真 中位数 0.88（偏保守） |
| 无变化（178 对） | 94% 判为"稳定"，6% 误报有发展 |

用真实照片发现并修掉的问题（合成照片没暴露）：
- **宽裂缝漏检**（宽于 ~10 像素的暗带被当成背景）→ 多尺度：原图、缩小 3 倍、9 倍各检一次再合并。
- **无变化却报"新增"**（最初误报 60%）：若隐若现的细纹一张过阈值、一张没过。→ 判"新增"时比较两张照片同一位置的裂缝响应强度，上次那里有一半以上就不算新增；比较前先把较清晰的一张模糊到一致；比较区边缘不计；新增至少 40 像素（约 1 cm）才报。
- **"变宽"误报**：改为最大宽度和整体平均宽度都明显增加才算。
- 暗色粗糙区域里纠缠成团的假裂缝：按骨架密度滤掉。

仍会误检的：砌块缝、施工缝、路缘、照片上的文字等细长暗线（它们前后都在，不影响"新增"判断，但会计入裂缝总长）；沥青等特别粗糙的表面漏检较多。

## 已知限制

- **只适用于近似平面**：单应矩阵假设拍摄对象是平面。U 肋折角、曲面、凹凸明显的构件需要后续扩展（分面或三维模型）。
- **畸变模型只有一个径向系数**：普通手机主摄、广角都够用；鱼眼镜头或强烈的切向畸变不在范围内。表面纹理太少时无法估计畸变（这时 k=0），建议用主摄、测区放在画面中部。
- **裂缝检测是传统图像处理**（黑帽 + 线段滤波 + 骨架），不需要训练数据、离线可用；但混凝土麻面、施工缝、模板接缝、划痕等细长暗线可能被当成裂缝（会出现在"原有裂缝"里，比较新增时影响不大）。真实照片验证后如误检多，再加一个小的分割模型替换"找裂缝"这一步，测量部分不变。
- **毫米换算假设裂缝与二维码在同一平面**：二维码贴在裂缝旁 30–50 cm 内；隧道二衬等曲面上离码越远误差越大。参考照片里读不到码（大场景扫码后拍全景）时只能用像素。
- **镜头朝向**依赖手机指南针，钢轨、钢结构、隧道内附近误差可能很大；它只用来排除方向明显不同的测点，不单独决定归类。
- **定位只做辅助**：位置只用来缩小候选范围，最终仍要画面特征吻合才自动归类；室内、隧道、桥下 GPS 可能偏几十到上百米，此时会退回纯特征识别或让你手选。同一地点（几十米内）背景相似的多个测区，仍需贴二维码区分。
- **大场景先扫码再拍时，照片里没有靶标**：对齐只靠画面特征（状态为"特征对齐"），场景纹理要足够丰富。参考照片若当初是贴近二维码拍的特写，后退拍全景会对不上，请把一张全景复拍"设为参考照片"。
- **只测过合成照片和模拟器**：真机实拍效果还要验证。反光区域现在会被排除而不是误报，但被排除的地方也就看不到变化，反光大时应重拍。
- 渗水、泛碱靠颜色明暗判断，和阴影、潮湿、污渍可能混淆；单凭一对照片无法完全区分，结论里会提示人工确认。
- **位移只量照片平面内的移动**：画面里有不同深度的构件（凸出的支座、背景）时，拍摄角度变化造成的视差可能被当成位移，结论里会提示。病害检测（面状、位移、标记线、部件）只在合成样例上验证过，还没有真实现场照片。
- 数据存在手机应用内部，卸载即删除。可以按测点导出 ZIP（含表格），没有云同步。升级 App 会保留已有数据。
- 安装包是调试签名，适合内部试用；正式分发前要换正式签名。

### 在另一台电脑上复现

仓库里不带的东西（都能重新生成）：`.venv/`、`复拍对齐相机.apk`、`samples/results/`、`deploy/dist/`、`android/local.properties`。`real_data/`（DeepCrack 数据集，仅限非商业研究）不进仓库，需要时自己下载。

```bash
git clone https://github.com/DamiennnWang/reshoot-align-camera.git && cd reshoot-align-camera

# 1. Python（3.9 以上，版本已锁定在 python/requirements.txt）
python3 -m venv .venv && .venv/bin/pip install -r python/requirements.txt
cd python && ../.venv/bin/python synth_test.py && ../.venv/bin/python test_hard.py && ../.venv/bin/python test_defects.py && cd ..

# 2. 安卓（JDK 17 + Android SDK 34；SDK 路径写进 android/local.properties：sdk.dir=/你的/Android/sdk，或设环境变量 ANDROID_HOME）
cd android && ./gradlew assembleDebug && cd ..
cp android/app/build/outputs/apk/debug/app-debug.apk 复拍对齐相机.apk

# 3. 网站（可选）
.venv/bin/python deploy/build_site.py
```

- 调试签名文件 `android/app/debug.keystore` 在仓库里，两台电脑编出的 APK 签名一致，手机上直接覆盖安装、数据保留。
- `samples/` 里的合成照片已经在仓库里；`synth_test.py` 只重新生成 `samples/results/` 和设备测试要用的结果。
