# 复拍对齐相机

同一个位置、不同时间拍的照片，自动**归类 → 对齐 → 对比变化**。

- 画面里有**二维码**：按码归到对应系列，再用码的四个角 + 三个圆点 + 照片自身纹理一起对齐，精度最高，还能发现靶标被移动。
- **没有二维码**：靠照片自身的图像特征，自动判断属于哪个系列。只有一个系列明显吻合时才自动归入。几个位置长得很像（背景相同）时，会提示"有歧义"，请你贴码或手选，不会乱归。
- 拍照时实时引导：显示参考照片的取景框和半透明叠加，提示"靠近 / 后退 / 左移 / 转一点"，对准后快门变绿。

## 目录

| 路径 | 内容 |
|---|---|
| `复拍对齐相机.apk` | 安卓安装包（Android 8.0 以上、64 位手机） |
| `targets/` | 可打印靶标（A4，100% 比例打印） |
| `android/` | 安卓 App 源码（Kotlin + Jetpack Compose + CameraX + ML Kit + OpenCV） |
| `python/` | 电脑端同一套算法：用真实照片调参、批量归档；`defects.py` 是病害检测基元（与 App 的 `Defects.kt` 同一套） |
| `samples/` | 合成测试照片和真值（`python/synth_test.py` 生成） |

## 手机上怎么用

1. **安装**：把 `复拍对齐相机.apk` 传到手机，打开安装（需要允许"安装未知来源应用"）。
2. **准备靶标（可选）**：打印 `targets/targets_B01-Z023.pdf`，剪下二维码和 3 个圆点贴在测区周围。
   - 圆点要分散、不在一条直线上，不要遮挡要观察的病害。
   - 贴好后保持不动。
   - 想先试一下，可以把下半页"试验布局"整张贴在硬板上拍。
3. **第一次拍**：首页点「扫码 / 拍照」。
   - **大场景（推荐）**：先靠近二维码扫一下，顶部出现「已扫码：新编号」后**后退**，把整个场景拍进画面再按快门。二维码在照片里很小、甚至不入镜都可以，编号用刚才扫到的。
   - 小范围：直接连二维码一起拍，确认绿圈圆点（点按可增减），然后保存。
   - 无二维码：起个名字建系列。允许定位的话会记下拍摄位置，以后按**位置 + 画面特征**自动识别。
   - 这张就是**参考照片**，以后的照片都和它比。
4. **以后复拍**：在系列页点「复拍」，或首页「扫码 / 拍照」后扫码。扫码后系列就**锁定**了（顶部有锁形提示，可点「解锁」），离开二维码、后退到参考位置也不会丢；按半透明参考和提示对准，快门变绿后拍。
   - 没有二维码时：附近（按手机定位）的系列里按画面特征自动识别；背景相似、只看画面分不清的两个地方，只要相距超出定位误差，就能靠位置区分。离所有系列都很远时不会乱猜，会让你手选。拍完自动对齐、对比，结果有五种看法：
   - **滑动**：左参考、右新图，拖动分界线
   - **叠加**：调新图透明度
   - **闪烁**：两图交替显示，变化处会"跳"
   - **变化**：红色加黄框是**结构变化**（裂缝、剥落、新物体），计入变化率；浅蓝加蓝框是**明暗变化**（阴影、水渍、光照不均），单独列出、不计入变化率；灰白是**反光/过曝**，未参与比较
   - **原图**：未对齐的原始照片
   - 有反光、模糊、偏暗时，对比页顶部会给出**拍摄质量提示**，可一键「删除并重拍」
   - 系列页顶部有**结构变化走势**图（两张以上复拍后出现），看病害是否在发展
   - **镜头朝向**：拍照时记录镜头朝向（北偏多少度）和俯仰角。同一点位不同方向的照片属于不同系列：识别时只在**位置附近且朝向吻合**（±60°、俯仰 ±30°）的系列里找；复拍时相机页提示"比参考偏右 20°，向左转"。附近有钢轨、钢结构时指南针可能不准，会提示"手机画 8 字校准"，此时只记录俯仰角。
   - **病害结论**：按测点类型给出（见下文“测点病害类型”）。只测裂缝时，对比页顶部的「病害结论」给出裂缝条数、总长、最大宽度、比上次新增的长度和判定（稳定 / 延长 / 变宽 / 新增），「标注」视图里原有裂缝黄色、新增部分红色。参考照片里有二维码时自动换算成毫米（二维码默认 40 mm，可在系列页菜单「二维码尺寸」修改，或把尺寸写进码里如 `K12+345;40mm`）；没有码时用像素表示。
   - 系列页的走势图可切换"结构变化 / 裂缝总长"，并给出系列结论，如"共 5 次复拍（120 天）：裂缝总长 132.7 → 192.1 mm，平均每 30 天 +14.8 mm；判定：持续发展"。
5. **任选两次对比**：对比页上方「对比基准」默认是参考照片，可以改选同系列的任意一张，比如上一次，用来看"这个月比上个月"的变化。
6. **分享**：对比页右上角的分享按钮，把变化图、对齐图、基准图和说明文字发到微信、邮件等。
7. **导入**：首页右上角「导入」可以选相册照片；也可以在相册或其他相机里"分享"给本应用。多张照片会逐张自动归类，遇到需要确认的会停下来问你。

### 对齐状态的含义

| 状态 | 含义 | 建议 |
|---|---|---|
| 已对齐 | 靶标和表面纹理两套独立依据结果一致 | 可直接用 |
| 特征对齐 | 无靶标，按照片纹理对齐 | 一般可用 |
| 待确认 | 靶标正常，但表面太光滑，无法用纹理复核 | 人工看一眼叠加图 |
| 圆点异常 | 某个圆点不见了或位置变了（已自动剔除） | 检查圆点是否脱落、被遮挡 |
| 需复核 | 靶标和表面纹理对不上，靶标可能被整体移动过 | 一定要人工核对 |

"整体相似度"低于 0.5 时会单独提示：可能拍的不是同一处，或表面整体变了（翻新、积水、遮挡）。

## 测点病害类型（小场景）

每个测点建档时选它拍什么（可多选），以后复拍自动按类型分析；在系列页菜单「病害类型」可以改，改完已有照片会重新分析。什么都不选 = 通用（裂缝 + 面状 + 位移）。

| 分组 | 类型 | 手机上给出 | 适用 |
|---|---|---|---|
| 线状 | 裂缝 | 条数、总长、最大宽度、比上次新增多少 | 混凝土裂缝、焊缝裂纹、轨枕裂纹 |
| 面状 | 剥落/掉块、渗水/水渍、泛碱/白化、锈蚀/涂层 | 每处的类别和面积（cm²） | 二衬掉块、渗漏水、泛碱、钢构件锈蚀与涂层剥落 |
| 位移 | 伸缩缝/接缝、错台/位移 | 一侧相对另一侧移动多少毫米，分解为“张开/闭合”和“错动” | 伸缩缝、管片接缝、支座、轨缝、扣件移位 |
| 部件 | 螺栓、扣件/部件 | 防松标记线：正常 / 疑似松动（转角）/ 残缺；部件疑似缺失或新增 | 钢结构螺栓群、轨道扣件、声屏障螺栓 |

结论统一分四级：**无变化 / 轻微 / 明显 / 建议重点关注**（只选“裂缝”的测点仍用 稳定 / 延长 / 变宽 / 新增）。对比页「标注」视图里：A = 面状变化（红 剥落、橙 锈蚀、蓝 渗水、紫 泛碱），D = 整体位移（箭头为方向），M = 防松标记（绿 正常、红 疑似松动、橙 残缺），P = 部件变化，编号和结论卡里的明细一一对应。

**类型写进二维码，现场不用选**：在编号后面用分号加类型，扫码建档时自动选好，例如 `B01-Z023;40mm;螺栓`、`Q12-03;伸缩缝,裂缝`、`T7;渗水;掉块`（也认英文 `crack / joint / offset / spall / seep / effl / rust / bolt / part`）。

**各类怎么拍**

- **螺栓**：用红色或黄色油漆，在螺母、垫片和钢板上画一条连续直线（防松标记）。螺母转动后这条线会断开、错开，App 量出转角。白色标记线目前识别不了。
- **伸缩缝、接缝、支座**：二维码贴在缝的一侧，画面里两侧都要拍进去，各占一部分。量的是“照片平面内”的移动（张开、错动）；管片错台这种垂直于墙面的高差，正对着拍看不出来，要斜着沿缝拍，或在缝边放一把小角尺。
- **剥落、渗水、泛碱、锈蚀**：正对表面拍，二维码贴在 30–50 cm 内。渗水、泛碱按颜色明暗判断，可能和阴影、潮湿、污渍混淆，结论里会提示人工确认。
- 手机上只给初步判断；要做精细识别，在系列菜单「导出全部」，ZIP 里每张照片有 `findings.json`（区域轮廓、位移向量、标记线角度等，坐标都在参考照片坐标系下）和标注图，`zone.json` 是测点信息。

**合成样例测试**（`python/make_defect_samples.py` 生成，`python/test_defects.py` 和设备端 `DefectsDeviceTest` 用同一批样例、同一判定标准；“今天”那张都换了角度、偏暖偏暗、有光照梯度）：12 个用例全部通过。

| 用例 | 真值 | 手机实测 |
|---|---|---|
| 剥落 / 锈蚀 / 渗水 / 泛碱 | 20.4 / 12.4 / 43.5 / 19.1 cm² | 类别全对；面积 22.8 / 13.9 / 49.2 / 21.1 cm²（偏大 10–15%，边缘过渡区计入） |
| 错台（错动） | 3.0 mm | 错动 3.0 mm |
| 接缝张开 | 2.0 mm / 1.0 mm | 张开 2.1 mm / 1.0 mm |
| 螺栓：1 个转 25°、1 个缺失 | — | 疑似松动（转角约 26°）+ 标记残缺 + 部件疑似缺失 |
| 螺栓：1 个转 10° | — | 疑似松动（转角约 11°） |
| 三组无变化对照 | — | 均无误报 |

**检测下限**（1 米左右拍摄、二维码 40 mm、约 0.23 mm/像素，`python/probe_limits.py`）：剥落/掉块约 1 cm²；位移约 1 mm（4 像素），0.5 mm 测不出；螺母转角约 10°，5° 测不出。强光照差（一侧暗一半、明显偏色）无误报。

## 算法要点

两端实现的是同一套算法：`python/fieldalign.py`，以及它的 Kotlin 移植 `android/.../align/AlignEngine.kt`。修改时两边要同步。

0. **镜头畸变**：先用宽松阈值做特征匹配，估计两张照片各自的径向畸变系数 k（x_d = x_u·(1+k·r²)）。估计分两遍，第二遍剔除残余误匹配。后续几何计算都在去畸变坐标下进行，变换图像时再把畸变加回去。残差改善不明显时 k 取 0，不做校正。
1. **找靶标**：
   - 二维码：OpenCV 读码，取四角并做亚像素细化；读不出时，安卓端用 ML Kit 再试；还不行就先按特征对齐，把码所在区域摆正放大后再解码。
   - 圆点：自适应阈值找深色圆形，按圆度、实心度、对比度、与码的大小比例筛选；同心候选只留最小的。
2. **初始对齐**：用码四角算单应矩阵，把参考照片的圆点"预测"到新照片上，就近配对。圆点不需要编号；四种角点顺序都试一遍，所以倒着拍也行。
3. **补找圆点**：全局没找到的圆点，把预测位置附近摆正到参考视角再找（强透视下圆点很扁）。每找到一个，就用三个定位块角加已找到的圆点重算预测矩阵，再找下一个。
   **圆点是否移动**：
   - 表面纹理可靠时，直接用特征矩阵判断。
   - 纹理不可靠时，用留一法：去掉某个点用其余点拟合，看它偏离多少。阈值取"0.3 倍新照片中的圆点视直径"和"3 倍外推不确定度"中较大的。
   - 至少剩 3 个圆点才继续剔除，再少就无从判断谁动了。
4. **图像特征复核**：遮掉靶标后，SIFT 特征匹配加 RANSAC，独立算出另一个矩阵（无码识别和取景引导为了速度用 ORB）。两者在靶标点上的偏差小于阈值才算"已对齐"；纹理丰富却对不上，判为"需复核"。
5. **融合精算**：靶标点和特征内点一起重新拟合，每个点同等权重。码的第 3 个角（右下角，没有定位块）是推算的，不参与精算。直接匹配的特征不够时（多半是视角太斜），先用靶标矩阵把新照片摆正，再匹配一次。
6. **对比**：
   - 只在"匹配点覆盖的同一平面区域"内比较，自动排除墙外背景的视差。
   - 新照片分辨率更低时（拍得远），在较低的分辨率下比较。
   - 光照归一化（除以局部均值），差分时允许 ±1 像素错位。
   - 用中位数 + MAD 的自适应阈值，再去掉小连通域。
   - **结构 / 明暗分类**：先求两图的对数亮度比，再做大窗口中值滤波。阴影、水渍是乘性变暗，对数比呈台阶状，中值能保留下来；裂缝是细线，会被中值去掉。所以中值之后的残差大，就是结构变化，残差小就是明暗变化。
7. **无码识别**：新照片和每个系列的参考照片做特征匹配。最佳候选至少 40 个内点、覆盖 12% 以上，且不少于第二名的 2 倍，才判为"唯一"。

### 测试结果（合成照片，有真值）

| 用例 | 状态 | 对齐误差（均值/最大，2000 像素宽） |
|---|---|---|
| 正常复拍 | 已对齐 | 0.02 / 0.05 px |
| 裂缝延长 | 已对齐，变化处被框出 | 0.01 / 0.04 px |
| 斜拍 + 光照变化 | 已对齐 | 0.02 / 0.07 px |
| 相机倒拿 180° | 已对齐 | 0.02 / 0.05 px |
| 一个圆点移动 23mm | 圆点异常（已剔除） | 0.01 / 0.05 px |
| 整套靶标贴到别的墙 | 需复核，相似度 0.10 | — |
| 远 + 极斜 + 模糊（码边长仅 65px） | 已对齐 | 1.3 / 3.9 px（约合新照片 0.4 px） |
| 完全无纹理墙面 | 待确认（只靠靶标） | 0.31 / 1.09 px |
| 无码系列识别 | 唯一 / 有歧义 / 未匹配均判断正确 | 纯特征对齐 0.01 / 0.02 px |
| 镜头畸变 k=−0.12（两张相同） | 已对齐，k 估计 −0.120 | 0.02 / 0.10 px，假变化 0 |
| 镜头畸变 k=−0.20（两张相同） | 已对齐，k 估计 −0.200 | 0.02 / 0.05 px，假变化 0 |
| 两部手机畸变不同（−0.05 / −0.18） | 已对齐，k 估计 −0.050 / −0.180 | 0.02 / 0.12 px，假变化 0 |

**这一版做过的精度改进**（每项都有测试对照）：

| 改进 | 效果 |
|---|---|
| 对齐特征由 ORB 换成 SIFT | 倒拿误差 1.15 → 0.13 px |
| 融合时靶标点和特征点等权重（原先靶标占 1/5） | 普通用例误差再降到 0.02 px |
| 畸变优化改为模式搜索，正则项减小 | k 估计误差 0.013 → 0.001 |
| 圆点检测找全部轮廓（原先只找外轮廓） | 纹理强时圆点不再漏检 |
| 圆点摆正到参考视角再找，找到后迭代修正预测 | 极斜视角下扁椭圆圆点能找到 |
| 圆点移动判断：有纹理时用特征矩阵，否则用留一法，阈值考虑外推不确定度 | 小码远拍不再把三个圆点全判为移动 |
| 直接匹配不够时，先摆正新照片再匹配特征 | 极斜视角也能完成纹理复核 |
| 新照片读不出码时，按特征摆正放大后再解码（安卓端另有 ML Kit 后备） | 码小、码糊也能走完整流程 |
| 在两张照片中较低的分辨率下做对比 | 远拍时假变化减少 |

没有畸变校正时，k=−0.12 的照片会出现 2.6% 的假变化，还会被误判为"圆点异常"。

| 光影用例 | 结构变化 | 明暗变化 |
|---|---|---|
| 软阴影 | 0 | 3.5%（正确归为明暗） |
| 硬阴影 | 0 | 6.5%（正确归为明暗） |
| 硬阴影 + 裂缝延长 | 1 处（裂缝） | 6.5% |
| 裂缝延长 | 1 处 | 0 |

没有这一分类时，一道硬阴影会产生 4.7% 的"变化"，把裂缝完全淹没。

### 拍摄退化压力测试（`test_robustness.py`）

模拟手机实拍常见问题，12 个用例全部对齐（误差均 ≤ 0.16 px），结构变化判断全部正确：

| 用例 | 结果 |
|---|---|
| 强噪声 + JPEG 质量 60（含/不含裂缝） | 无假变化；裂缝检出 |
| 欠曝（亮度 ×0.35）、偏色 | 无假变化 |
| 过曝（亮度 ×1.7，大片死白） | 无假变化；死白区排除并提示"过曝" |
| 运动模糊 11px（含/不含裂缝） | 无假变化；裂缝检出；提示"新照片比参考模糊" |
| 镜面反光（含/不含裂缝） | 无假变化；反光区排除并提示；裂缝检出 |
| 竖拍（照片旋转 90°） | 正常 |
| 低分辨率 1600px（含/不含裂缝） | 无假变化；裂缝检出 |

修复前过曝会产生 354 处假变化（2.2%），反光 14 处（0.9%），运动模糊 2 处。对应改进：
- **反光/过曝/死黑排除**：任一张饱和的像素，加上与饱和核连通、朝"变亮"方向偏离的光晕，不参与比较，在变化图中显示为灰白，并给出占比。
- **清晰度匹配**：比较前自动把较清晰的一张模糊到与另一张一致（搜索最佳 σ），手抖、对焦偏差不再产生假变化。
- **拍摄质量提示**：反光超过 2.5%、新照片明显更糊、照片偏暗时，对比页顶部出现提示，可一键"删除并重拍"。

安卓端在模拟器上跑同样的照片（含畸变、光影、退化用例），状态和变化判断全部一致。
处理速度：单张约 1.7 秒；同一系列连续复拍时缓存参考照片的特征和解码图，约 1.0 秒（优化前 2.5 秒）。

### 裂缝测量精度（`test_measure.py`，合成照片，有真值）

只用参考照片里 40 mm 二维码换算比例；工作图约 0.23 mm/像素（相当于 4000 万像素手机在约 1 米处拍）。

| 用例 | 比例 mm/px 测/真 | 总长 mm 测/真 | 最大宽 mm 测/真 | 新增 mm 测/真 | 判定 |
|---|---|---|---|---|---|
| 0.25 mm 细裂缝 | 0.228 / 0.228 | 180 / 179 | ≤0.57（标出"接近分辨率极限"） | 62.2 / 62.4 | 延长 |
| 0.5 mm | 0.228 / 0.228 | 192 / 179 | 0.67 / 0.50 | 62.0 / 62.4 | 延长 |
| 1.0 mm | 0.228 / 0.228 | 192 / 179 | 1.02 / 1.00 | 62.2 / 62.4 | 延长 |
| 0.5 mm，粗糙表面 | 0.228 / 0.228 | 183 / 179 | 0.68 / 0.50 | 59.4 / 62.4 | 延长 |
| 无裂缝（普通 / 粗糙） | — | 0 条 | — | — | 无裂缝 |

- 比例尺误差 < 1%；新增长度误差 < 5%；总长偏长约 7%（裂缝两端、细小分叉）。
- 宽度误差约 1 像素（这里约 0.2 mm）。**平均宽度小于 2 像素的裂缝测不准**，App 会标"≤"并提示靠近拍摄。要测 0.2 mm 级的裂缝宽度，需要在 0.5 米内拍或用长焦。
- 手机端（Kotlin）结果与 Python 一致，测量耗时约 2.5–3 秒/张（模拟器；多尺度和清晰度匹配后）。

### 真实裂缝照片验证（`eval_real.py`、`test_real_pairs.py`）

数据：公开数据集 DeepCrack（真实裂缝照片 + 人工标注掩膜；**仅限非商业研究使用**，下载到 `real_data/deepcrack/`，不随 App 分发）。

**1. 检测对不对**（237 张测试集，与人工标注逐像素比，容差 5 像素）

| | 精确率（检出的有多少是真裂缝） | 召回率（真裂缝检出了多少） |
|---|---|---|
| 全部 | 91% | 84% |
| 标注宽 3–6 px | 85% | 83% |
| 标注宽 6–12 px | 93% | 86% |
| 标注宽 >12 px | 94% | 80% |

逐张中位数：精确率 98%、召回率 94%、检出长度/标注长度 1.03。完全漏检 2 张。

**2. 前后对比准不准**（真实纹理造"前后两次"：把真实裂缝后 40% 修补掉当"上次"，原图加随机透视、亮度/对比度、模糊、噪声当"这次"，纯图像特征对齐后比较）

| | 结果 |
|---|---|
| 裂缝延长（175 对） | 99% 判为"延长/新增"；新增长度 测/真 中位数 0.88（偏保守） |
| 无变化（178 对） | 94% 判为"稳定"，6% 误报有发展 |

用真实照片发现并修掉的问题（合成照片没暴露）：
- **宽裂缝漏检**（宽于 ~10 像素的暗带被当成背景）→ 多尺度：原图、缩小 3 倍、9 倍各检一次再合并。
- **无变化却报"新增"**（最初误报 60%）：若隐若现的细纹一张过阈值、一张没过。→ 判"新增"时比较两张照片同一位置的裂缝响应强度，上次那里有一半以上就不算新增；比较前先把较清晰的一张模糊到一致；比较区边缘不计；新增至少 40 像素（约 1 cm）才报。
- **"变宽"误报**：改为最大宽度和整体平均宽度都明显增加才算。
- 暗色粗糙区域里纠缠成团的假裂缝：按骨架密度滤掉。

仍会误检的：砌块缝、施工缝、路缘、照片上的文字等细长暗线（它们前后都在，不影响"新增"判断，但会计入裂缝总长）；沥青等特别粗糙的表面漏检较多。

## 已知限制

- **只适用于近似平面**：单应矩阵假设拍摄对象是平面。U 肋折角、曲面、凹凸明显的构件需要后续扩展（分面或三维模型）。
- **畸变模型只有一个径向系数**：普通手机主摄、广角都够用；鱼眼镜头或强烈的切向畸变不在范围内。表面纹理太少时无法估计畸变（这时 k=0），建议用主摄、测区放在画面中部。
- **裂缝检测是传统图像处理**（黑帽 + 线段滤波 + 骨架），不需要训练数据、离线可用；但混凝土麻面、施工缝、模板接缝、划痕等细长暗线可能被当成裂缝（会出现在"原有裂缝"里，比较新增时影响不大）。真实照片验证后如误检多，再加一个小的分割模型替换"找裂缝"这一步，测量部分不变。
- **毫米换算假设裂缝与二维码在同一平面**：二维码贴在裂缝旁 30–50 cm 内；隧道二衬等曲面上离码越远误差越大。参考照片里读不到码（大场景扫码后拍全景）时只能用像素。
- **镜头朝向**依赖手机指南针，钢轨、钢结构、隧道内附近误差可能很大；它只用来排除方向明显不同的系列，不单独决定归类。
- **定位只做辅助**：位置只用来缩小候选范围，最终仍要画面特征吻合才自动归类；室内、隧道、桥下 GPS 可能偏几十到上百米，此时会退回纯特征识别或让你手选。同一地点（几十米内）背景相似的多个测区，仍需贴二维码区分。
- **大场景先扫码再拍时，照片里没有靶标**：对齐只靠画面特征（状态为"特征对齐"），场景纹理要足够丰富。参考照片若当初是贴近二维码拍的特写，后退拍全景会对不上，请把一张全景复拍"设为参考照片"。
- **只测过合成照片和模拟器**：真机实拍效果还要验证。反光区域现在会被排除而不是误报，但被排除的地方也就看不到变化，反光大时应重拍。
- 渗水、泛碱靠颜色明暗判断，和阴影、潮湿、污渍可能混淆；单凭一对照片无法完全区分，结论里会提示人工确认。
- **位移只量照片平面内的移动**：画面里有不同深度的构件（凸出的支座、背景）时，拍摄角度变化造成的视差可能被当成位移，结论里会提示。病害检测（面状、位移、标记线、部件）只在合成样例上验证过，还没有真实现场照片。
- 数据存在手机应用内部，卸载即删除。可以按系列导出 ZIP（含表格），没有云同步。升级 App 会保留已有数据。
- 安装包是调试签名，适合内部试用；正式分发前要换正式签名。
